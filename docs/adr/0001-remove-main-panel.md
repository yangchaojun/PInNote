# ADR-0001: 移除主面板，Pin 窗口即全部界面

日期：2026-09-05 · 状态：已接受 · 决策者：产品 grilling（wayfinder map「Pin 窗口即全部界面」）

## 背景

PinNote v1 有一个主面板（笔记列表 + 编辑器 + 回收站 + 搜索）和可选的桌面 pin 窗口。主面板承担了新建、找回、恢复、删除等全部入口职能。产品目标是纯便签形态：打开即写，桌面上见到的就是全部。

## 决策

1. 移除主窗口与主面板全部 UI（列表/编辑器/回收站/搜索/快捷键模态的旧内容）。
2. 每条 live 笔记恒对应一个 Pin 窗口；应用启动恢复全部 live 笔记的窗口，无笔记时静默驻留。
3. 新建入口 = 全局 `⌘⌥N` 直接开新 pin 窗口 + 菜单栏项。
4. 「固定 / 取消固定」概念退役：关窗 = 收起（数据保留，重启恢复），删除（`⌘⌫`/菜单栏）进回收站。`Pinned` 字段与 `SetPinned` API 后端冻结。
5. 空白笔记（content trim 后为空）关窗即硬删，防 `⌘⌥N` 产生垃圾数据。

## 理由

- 主面板移除后不存在任何"再打开"入口，只有"笔记恒有窗口 + 启动全恢复"（Stickies 式）能保证数据永远可达；否则关窗即数据滞留。
- 备选的"关窗 = 取消固定"会让笔记永久不可见；"关窗 = 删除"误触代价过高（回收站无 UI）。
- 空白硬删而非软删：空白内容无数据价值，不占 60 天回收站名额。

## 影响

- 搜索、回收站恢复/彻底删除、笔记切换等能力整体出界（60 天 purge 后台逻辑保留）。
- 多窗口同步靠既有 `notes:changed` 广播 + react-query invalidation，语义不变。
- 后端 `RestoreNote`/`DeleteNoteForever`/`EmptyTrash` 等无 UI 调用方，冻结保留供 purge 与未来找回入口使用。
